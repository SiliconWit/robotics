A robot can only turn its joints, but the work is at a point in space: a weld seam, a screw hole, a part on a tray. With the wrong joint angles the tool arrives a few millimetres away and the weld is scrap. Two calculations connect the angles to the point. Forward kinematics (FK) answers "the joints are at these angles, so where is the tool?" Inverse kinematics (IK) answers "the tool must be at this point, so which angles do I command?" This lesson solves both for a two-link welding arm. #ForwardKinematics #InverseKinematics #RoboticWelding

## Real-World Engineering Challenge: Robotic Welding of Curved Seams

<InArticleAd />

A robot arm welds a curved seam on a pressure vessel. The arm moves in one flat plane and has two revolute (turning) joints, so it is called a planar 2R arm. Its link lengths are $L_1 = 400$ mm and $L_2 = 300$ mm. The seam is an arc, given as a row of points called waypoints, and the torch must be within about a millimetre of each one. The far part of the seam comes within about 120 mm of the edge of the region the arm can reach.

:::note[Engineering Questions]
1. How far can the robot reach, and which region of the plane can the torch cover?
2. For one point on the seam, how many pairs of joint angles put the torch there, and which pair should the controller use?
3. What changes when a target comes close to the edge of the reachable region?
4. How does the system find a point it cannot reach before it moves?
:::

### Why This Problem Matters in Industry

A torch that is off the seam gives a weld that is not fully fused or burns through the plate. The controller uses inverse kinematics to turn the next point of the seam into joint angles, and forward kinematics to check from the measured angles that the torch arrived.

## Forward Kinematics: From Joint Angles to End-Effector Position

<InArticleAd />

The joint angles are known. Where is the end-effector (the tool at the end of the arm)? We answer first for the planar 2R arm with plain trigonometry, then with a method that works for any number of joints.

### FK for a 2R Planar Robot

```text
  2R planar arm: the two joint angles

                        hand (x_e, y_e)
                       /
                      /  link 2, length L2
                     /
          elbow     o . . . . .  link 1 continued
        (x1, y1)   /   theta2 = turn of link 2
                  /             away from this line
                 /  link 1, length L1
                /
               /  theta1
  base (0,0)  o-------------------------> x
```

Link 1 has length $L_1$ and points at the angle $\theta_1$, measured counterclockwise from the $x$ axis. Link 2 has length $L_2$. Its angle $\theta_2$ is measured from the direction of link 1, counterclockwise positive, so link 2 points at $\theta_1 + \theta_2$ in the plane.

Walk from the base to the hand. A link of length $L$ that points at an angle $\phi$ moves you $L \cos\phi$ along $x$ and $L \sin\phi$ along $y$. After link 1 you are at the elbow:

$$
x_1 = L_1 \cos(\theta_1), \quad y_1 = L_1 \sin(\theta_1)
$$

Add link 2 to reach the end-effector:

$$
x_e = L_1 \cos(\theta_1) + L_2 \cos(\theta_1 + \theta_2)
$$

$$
y_e = L_1 \sin(\theta_1) + L_2 \sin(\theta_1 + \theta_2)
$$

Every pair $(\theta_1, \theta_2)$ gives exactly one position.

**Worked example.** Take $\theta_1 = 45°$ and $\theta_2 = -30°$. Link 2 points at $45° - 30° = 15°$.

$$
x_e = 400 \cos 45° + 300 \cos 15° = 282.8 + 289.8 = 572.6 \text{ mm}
$$

$$
y_e = 400 \sin 45° + 300 \sin 15° = 282.8 + 77.7 = 360.5 \text{ mm}
$$

The elbow is at (282.8, 282.8) mm and the torch is at (572.6, 360.5) mm ✅

:::note[Angle Convention]
A common mistake is to measure $\theta_2$ from the $x$ axis. It is measured from link 1: the angle the elbow motor turns.
:::

### FK Implementation in Python

The program repeats the worked example and prints the same two positions.

```python
import numpy as np
import matplotlib.pyplot as plt

def forward_kinematics_2R(L1, L2, theta1, theta2):
    """Compute end-effector position for a 2R planar robot.

    Args:
        L1: Length of link 1 (mm)
        L2: Length of link 2 (mm)
        theta1: Joint 1 angle (radians), measured from +x axis
        theta2: Joint 2 angle (radians), relative to link 1

    Returns:
        (x_e, y_e): End-effector position in base frame (mm)
        (x_1, y_1): Elbow position in base frame (mm)
    """
    # Elbow (joint 2) position
    x1 = L1 * np.cos(theta1)
    y1 = L1 * np.sin(theta1)

    # End-effector position
    x_e = x1 + L2 * np.cos(theta1 + theta2)
    y_e = y1 + L2 * np.sin(theta1 + theta2)

    return (x_e, y_e), (x1, y1)

# Example: L1 = 400mm, L2 = 300mm
L1, L2 = 400, 300
theta1 = np.radians(45)   # 45 degrees
theta2 = np.radians(-30)  # -30 degrees relative to link 1

(x_e, y_e), (x1, y1) = forward_kinematics_2R(L1, L2, theta1, theta2)
print(f"Elbow:        ({x1:.1f}, {y1:.1f}) mm")
print(f"End-effector: ({x_e:.1f}, {y_e:.1f}) mm")
```

### Denavit-Hartenberg (DH) Parameter Convention

With six joints in 3D, the walk from base to hand is long and mistakes are easy. The Denavit-Hartenberg (DH) method replaces it with a table. You fix a frame (an origin with $x$, $y$ and $z$ axes) to each link, with $z$ along a joint axis. Four numbers then lead from one frame to the next.

```text
  Two neighbouring DH frames

  z_{i-1}                            z_i
    |                                 |
    |  d_i: slide along z_{i-1}       |
    |                                 |
    +--------> x_{i-1}                +--------> x_i
  frame i-1                         frame i
    |<------ a_i: slide along x_i --->|
```

| Parameter | Symbol | Description |
|-----------|--------|-------------|
| Joint angle | $\theta_i$ | Turn about $z_{i-1}$ that brings $x_{i-1}$ to $x_i$ (radians) |
| Link offset | $d_i$ | Slide along $z_{i-1}$ (mm) |
| Link length | $a_i$ | Slide along $x_i$ (mm) |
| Link twist | $\alpha_i$ | Turn about $x_i$ that brings $z_{i-1}$ to $z_i$ (radians) |

A revolute joint changes $\theta_i$ as it moves, and a prismatic (sliding) joint changes $d_i$. The other numbers are fixed by the way the robot is built.

The four moves, done in the order of the table, are written as one $4 \times 4$ matrix called a homogeneous transformation: its upper left $3 \times 3$ block holds the turn, and its last column holds the shift (see [Elementary Matrix Methods and Link Modeling](/education/spatial-mechanics/matrix-methods-link-modeling/)). The matrix from frame $i-1$ to frame $i$ is:

$$
T_i = \begin{bmatrix}
\cos\theta_i & -\sin\theta_i \cos\alpha_i & \sin\theta_i \sin\alpha_i & a_i \cos\theta_i \\
\sin\theta_i & \cos\theta_i \cos\alpha_i & -\cos\theta_i \sin\alpha_i & a_i \sin\theta_i \\
0 & \sin\alpha_i & \cos\alpha_i & d_i \\
0 & 0 & 0 & 1
\end{bmatrix}
$$

Forward kinematics is then one multiplication, in order from the base to the end-effector (ee), for an arm with $n$ joints:

$$
T_{\text{base}}^{\text{ee}} = T_1 \cdot T_2 \cdot T_3 \cdots T_n
$$

The last column of the result holds the position of the end-effector.

In our planar arm all joint axes are parallel, so $\alpha_i = 0$ and $d_i = 0$. The program below builds the table for the welding arm and prints (572.6, 360.5) mm, the position of the worked example ✅

:::note[This Lesson Uses Classical DH]
The matrix above is the **classical** version (1955). The **modified** version (Craig, 1986) places the frames differently and does the four moves in another order. A DH table from a robot manual works only with the version it was written for. [Robotics Toolbox for Python](https://petercorke.github.io/robotics-toolbox-python/) makes you choose: `RevoluteDH(...)` or `RevoluteMDH(...)`.
:::

```python
def dh_transform(theta, d, a, alpha):
    """Compute the 4x4 DH transformation matrix.

    Args:
        theta: Joint angle (rad)
        d: Link offset (mm)
        a: Link length (mm)
        alpha: Link twist (rad)

    Returns:
        4x4 numpy array (homogeneous transformation)
    """
    ct, st = np.cos(theta), np.sin(theta)
    ca, sa = np.cos(alpha), np.sin(alpha)

    return np.array([
        [ct, -st * ca,  st * sa, a * ct],
        [st,  ct * ca, -ct * sa, a * st],
        [0,   sa,       ca,      d     ],
        [0,   0,        0,       1     ]
    ])

def fk_from_dh(dh_table, joint_angles):
    """Compute FK from a DH parameter table.

    Args:
        dh_table: List of (a, alpha, d, theta_offset) for each joint
        joint_angles: List of joint angle values (rad)

    Returns:
        4x4 homogeneous transformation (base to end-effector)
    """
    T = np.eye(4)
    for i, (a, alpha, d, theta_offset) in enumerate(dh_table):
        theta = joint_angles[i] + theta_offset
        T = T @ dh_transform(theta, d, a, alpha)
    return T

# DH table for 2R planar robot
# (a, alpha, d, theta_offset)
dh_2R = [
    (400, 0, 0, 0),  # Link 1: a=400mm, planar
    (300, 0, 0, 0),  # Link 2: a=300mm, planar
]

# Test: same angles as before
q = [np.radians(45), np.radians(-30)]
T = fk_from_dh(dh_2R, q)
print(f"End-effector position from DH: ({T[0,3]:.1f}, {T[1,3]:.1f}) mm")
```

## Inverse Kinematics: From Target Position to Joint Angles

<InArticleAd />

Inverse kinematics is the harder question: from a known target position $(x_t, y_t)$, find the joint angles $(\theta_1, \theta_2)$ that put the end-effector there. Forward kinematics always has exactly one answer. Inverse kinematics can have none, one or several.

### Two answers for one target

Touch a point on the table with one fingertip: your elbow can be high or low, and the fingertip does not move. A two-link arm has the same choice, with two solutions for a target inside the reachable region, one for a target exactly on its edge, and none outside it.

The two solutions are mirror images in the line from base to target, and are named by where the elbow sits. For a target to the right of the base, as in all examples here:

- **Elbow-up:** the elbow is above the line from base to target. Link 2 turns clockwise from link 1, so $\theta_2 < 0$.
- **Elbow-down:** the elbow is below that line. Link 2 turns counterclockwise from link 1, so $\theta_2 > 0$.

```text
  One target, two solutions

  Elbow-up (theta2 < 0)         Elbow-down (theta2 > 0)

         elbow
          o                                   * target
         / \                                 /
        /   \                               /
       /     * target                      /
      /                                   /
base o                          base o---o elbow
```

A welding path must stay with one of the two. A change from one to the other in the middle of a seam swings the whole arm across.

### Two ways to solve it

The geometric method is an exact formula for simple arms. The numerical method corrects a guess step by step and works for any arm.

### Geometric Inverse Kinematics for a 2R Planar Robot

The base, the elbow and the target make a triangle. Two sides are the links, $L_1$ and $L_2$, and the third is the distance $r$ from the base to the target. All three sides are known, so the angles can be found.

**Step 1: Solve for $\theta_2$ using the law of cosines.**

By Pythagoras, the distance from the base to the target is given by:

$$
r^2 = x_t^2 + y_t^2
$$

The law of cosines relates the three sides of a triangle to one of its angles. The angle inside the triangle at the elbow is $180° - \theta_2$, and $\cos(180° - \theta_2) = -\cos\theta_2$, so the usual minus sign of the law becomes a plus:

$$
r^2 = L_1^2 + L_2^2 + 2 L_1 L_2 \cos(\theta_2)
$$

Solve for $\cos(\theta_2)$, and call it $c_2$:

$$
c_2 = \cos(\theta_2) = \frac{x_t^2 + y_t^2 - L_1^2 - L_2^2}{2 L_1 L_2}
$$

A cosine lies between $-1$ and $1$. If $c_2$ is outside that range, no triangle exists and the target cannot be reached. Otherwise two angles have this cosine, one positive and one negative:

$$
\theta_2 = \pm \arccos(c_2)
$$

The positive value is the elbow-down solution and the negative value is the elbow-up solution.

For the target (500, 200) mm with $L_1 = 400$ mm and $L_2 = 300$ mm:

$$
c_2 = \frac{500^2 + 200^2 - 400^2 - 300^2}{2 \times 400 \times 300} = \frac{40{,}000}{240{,}000} = 0.1667, \quad \theta_2 = \pm 80.41°
$$

:::note[Using atan2 for robustness]
The function `atan2(y, x)` gives the angle of the point $(x, y)$ seen from the origin, over the full circle. Programs use it in place of `arccos`, which loses accuracy when the arm is almost straight. They find $\sin(\theta_2) = \pm\sqrt{1 - c_2^2}$, choose its sign, and take $\theta_2 = \text{atan2}(\sin\theta_2, \cos\theta_2)$.
:::

**Step 2: Solve for $\theta_1$.**

The angle $\theta_1$ is the direction from the base to the target, minus the angle between link 1 and that direction. Seen from link 1, the hand is $k_1$ along the link and $k_2$ to its side:

$$
k_1 = L_1 + L_2 \cos(\theta_2), \quad k_2 = L_2 \sin(\theta_2)
$$

Then:

$$
\theta_1 = \text{atan2}(y_t, x_t) - \text{atan2}(k_2, k_1)
$$

For the target (500, 200) mm, $k_1 = 400 + 300 \times 0.1667 = 450$ mm and $k_2 = \pm 300 \times 0.9860 = \pm 295.8$ mm:

$$
\theta_1 = \text{atan2}(200, 500) - \text{atan2}(\pm 295.8, 450) = 21.80° \mp 33.32°
$$

- Elbow-down: $\theta_2 = +80.41°$, $\theta_1 = 21.80° - 33.32° = -11.52°$. The elbow is at (391.9, -79.9) mm, below the line to the target ✅
- Elbow-up: $\theta_2 = -80.41°$, $\theta_1 = 21.80° + 33.32° = 55.12°$. The elbow is at (228.7, 328.1) mm, above the line ✅

The program solves the same target and checks each solution with forward kinematics.

```python
def inverse_kinematics_2R(L1, L2, x_t, y_t):
    """Geometric IK for a 2R planar robot.

    Args:
        L1, L2: Link lengths (mm)
        x_t, y_t: Target position (mm)

    Returns:
        List of (theta1, theta2) solution tuples (radians).
        Returns empty list if target is unreachable.
    """
    r_sq = x_t**2 + y_t**2
    r = np.sqrt(r_sq)

    # Check reachability
    r_max = L1 + L2
    r_min = abs(L1 - L2)
    if r > r_max or r < r_min:
        print(f"Target ({x_t:.1f}, {y_t:.1f}) is unreachable.")
        print(f"  Distance: {r:.1f} mm")
        print(f"  Reachable range: [{r_min:.1f}, {r_max:.1f}] mm")
        return []

    # Solve for theta2
    cos_theta2 = (r_sq - L1**2 - L2**2) / (2 * L1 * L2)
    # Clamp for numerical safety
    cos_theta2 = np.clip(cos_theta2, -1.0, 1.0)
    sin_theta2 = np.sqrt(1 - cos_theta2**2)

    solutions = []
    # sign +1 gives theta2 > 0, sign -1 gives theta2 < 0.
    for sign in [+1, -1]:  # elbow-down (theta2 > 0), elbow-up (theta2 < 0)
        s2 = sign * sin_theta2
        theta2 = np.arctan2(s2, cos_theta2)

        # Solve for theta1
        k1 = L1 + L2 * cos_theta2
        k2 = L2 * s2
        theta1 = np.arctan2(y_t, x_t) - np.arctan2(k2, k1)

        solutions.append((theta1, theta2))

    return solutions

# Test: find joint angles for target (500, 200)
L1, L2 = 400, 300
target = (500, 200)
solutions = inverse_kinematics_2R(L1, L2, *target)

for i, (t1, t2) in enumerate(solutions):
    config = "Elbow-down" if t2 > 0 else "Elbow-up"
    print(f"Solution {i+1} ({config}):")
    print(f"  theta1 = {np.degrees(t1):.2f} deg")
    print(f"  theta2 = {np.degrees(t2):.2f} deg")

    # Verify with FK
    (xe, ye), _ = forward_kinematics_2R(L1, L2, t1, t2)
    print(f"  FK check: ({xe:.2f}, {ye:.2f}) mm")
    error = np.sqrt((xe - target[0])**2 + (ye - target[1])**2)
    print(f"  Position error: {error:.6f} mm")
```

### Numerical Inverse Kinematics Using Newton-Raphson Iteration

Many arms have no exact formula. The numerical method needs only forward kinematics. It works the way you park a car: see how far you are from the mark, correct, and look again. This scheme is called Newton-Raphson iteration.

In the steps below, $\mathbf{q}$ is the list of joint angles, $\mathbf{p}$ is the position of the end-effector, and the index $k$ counts the corrections.

<Steps>
1. Start with a first guess $\mathbf{q}_0$ for the joint angles.

2. Use forward kinematics to find where the end-effector is now: $\mathbf{p}_{\text{current}} = \text{FK}(\mathbf{q}_k)$.

3. Find the miss, from the current position to the target: $\Delta\mathbf{p} = \mathbf{p}_{\text{target}} - \mathbf{p}_{\text{current}}$.

4. If the length of the miss $\|\Delta\mathbf{p}\|$ is below a small tolerance $\epsilon$, stop. The answer is $\mathbf{q}_k$.

5. Compute the Jacobian matrix $J(\mathbf{q}_k)$ for the current angles (explained below).

6. Find the change of joint angles that removes the miss: $\Delta\mathbf{q} = J^{-1} \Delta\mathbf{p}$.

7. Apply it: $\mathbf{q}_{k+1} = \mathbf{q}_k + \Delta\mathbf{q}$.

8. Repeat from step 2.
</Steps>

**The Jacobian matrix** $J$ is a small table of sensitivities. Each entry says how far one coordinate of the end-effector moves when one joint turns by a small angle. Row 1 is for $x_e$ and row 2 for $y_e$. Column 1 is for $\theta_1$ and column 2 for $\theta_2$. From the two FK equations:

$$
J = \begin{bmatrix}
-L_1 \sin(\theta_1) - L_2 \sin(\theta_1 + \theta_2) & -L_2 \sin(\theta_1 + \theta_2) \\
L_1 \cos(\theta_1) + L_2 \cos(\theta_1 + \theta_2) & L_2 \cos(\theta_1 + \theta_2)
\end{bmatrix}
$$

So $J$ turns a small joint motion into a hand motion, and its inverse $J^{-1}$ in step 6 turns a wanted hand motion back into a joint motion. [Velocity Kinematics and the Jacobian](/education/robotics/velocity-kinematics-jacobian/) derives it.

:::note[Singularity Warning]
When the arm is straight or fully folded, both joints move the hand along the same line, and $J$ has no inverse. Such a pose is called a singularity. The program below uses a safer form of step 6, damped least squares: a small number (`damping`) keeps the correction limited.
:::

For the target (500, 200) mm and the default first guess, the program arrives in 6 corrections at $\theta_1 = -11.52°$ and $\theta_2 = 80.41°$. This is the elbow-down solution found by geometry.

```python
def jacobian_2R(L1, L2, theta1, theta2):
    """Compute the 2x2 Jacobian for a 2R planar robot.

    Args:
        L1, L2: Link lengths (mm)
        theta1, theta2: Joint angles (rad)

    Returns:
        2x2 numpy array (Jacobian matrix)
    """
    s1 = np.sin(theta1)
    c1 = np.cos(theta1)
    s12 = np.sin(theta1 + theta2)
    c12 = np.cos(theta1 + theta2)

    J = np.array([
        [-L1 * s1 - L2 * s12, -L2 * s12],
        [ L1 * c1 + L2 * c12,  L2 * c12]
    ])
    return J

def numerical_ik_2R(L1, L2, x_t, y_t,
                     q0=None, tol=1e-6, max_iter=100,
                     damping=1e-4):
    """Numerical IK using damped Jacobian iteration.

    Args:
        L1, L2: Link lengths (mm)
        x_t, y_t: Target position (mm)
        q0: Initial joint angle guess (rad). Defaults to [0.5, 0.5].
        tol: Convergence tolerance (mm)
        max_iter: Maximum iterations
        damping: Damping factor for singularity robustness

    Returns:
        (theta1, theta2): Joint angles (rad), or None if no convergence
        history: List of (iteration, error) tuples
    """
    if q0 is None:
        q0 = np.array([0.5, 0.5])
    else:
        q0 = np.array(q0, dtype=float)

    q = q0.copy()
    target = np.array([x_t, y_t])
    history = []

    for i in range(max_iter):
        # Current end-effector position
        (xe, ye), _ = forward_kinematics_2R(L1, L2, q[0], q[1])
        current = np.array([xe, ye])

        # Position error
        dp = target - current
        error = np.linalg.norm(dp)
        history.append((i, error))

        if error < tol:
            print(f"Converged in {i} iterations (error: {error:.2e} mm)")
            return tuple(q), history

        # Jacobian at current configuration
        J = jacobian_2R(L1, L2, q[0], q[1])

        # Damped least-squares inverse (Levenberg-Marquardt)
        # Avoids singularity issues
        JtJ = J.T @ J + damping * np.eye(2)
        dq = np.linalg.solve(JtJ, J.T @ dp)

        q += dq

    print(f"Warning: did not converge after {max_iter} iterations")
    print(f"  Final error: {error:.4f} mm")
    return tuple(q), history

# Test numerical IK
L1, L2 = 400, 300
target = (500, 200)

print("=== Numerical IK ===")
q_numerical, hist = numerical_ik_2R(L1, L2, *target)

if q_numerical:
    t1, t2 = q_numerical
    print(f"  theta1 = {np.degrees(t1):.2f} deg")
    print(f"  theta2 = {np.degrees(t2):.2f} deg")

    # Verify
    (xe, ye), _ = forward_kinematics_2R(L1, L2, t1, t2)
    print(f"  FK check: ({xe:.2f}, {ye:.2f}) mm")
```

## Workspace Analysis

<InArticleAd />

The workspace of a robot is the set of all points the end-effector can reach. For a planar 2R arm it is a ring between two circles centred on the base:

- The outer circle has radius $r_{\max} = L_1 + L_2$, the arm stretched straight. For the welding arm, $400 + 300 = 700$ mm.
- The inner circle has radius $r_{\min} = |L_1 - L_2|$, link 2 folded back along link 1. For the welding arm, $400 - 300 = 100$ mm.

If $L_1 = L_2$ the inner circle shrinks to the base and the whole disk can be reached.

A target in the ring has two solutions, a target exactly on either circle has one, and a target anywhere else has none. The program below marks 5,000 random poses of the welding arm and draws the two circles over them.

### Reachability Check

A controller should first test the target against the two circles. The function below also warns when a target is within 35 mm of either circle. Of its five test points, (710, 0) is outside by 10 mm, and (690, 0) and (80, 80) can be reached but receive the warning.

```python
def check_reachability(L1, L2, x_t, y_t):
    """Check if a target point is within the workspace.

    Args:
        L1, L2: Link lengths (mm)
        x_t, y_t: Target position (mm)

    Returns:
        dict with reachability status and margin information
    """
    r = np.sqrt(x_t**2 + y_t**2)
    r_max = L1 + L2
    r_min = abs(L1 - L2)

    reachable = r_min <= r <= r_max

    # Margin: how far inside the workspace boundary
    outer_margin = r_max - r     # positive = inside outer boundary
    inner_margin = r - r_min     # positive = outside inner boundary

    # Proximity warning
    boundary_threshold = 0.05 * r_max  # 5% of max reach
    near_boundary = (outer_margin < boundary_threshold or
                     inner_margin < boundary_threshold)

    return {
        'reachable': reachable,
        'distance': r,
        'r_max': r_max,
        'r_min': r_min,
        'outer_margin_mm': outer_margin,
        'inner_margin_mm': inner_margin,
        'near_boundary': near_boundary,
    }

# Test several target points
L1, L2 = 400, 300
test_points = [
    (500, 200, "Interior point"),
    (690, 0,   "Near outer boundary"),
    (710, 0,   "Outside workspace"),
    (80, 80,   "Near inner boundary"),
    (300, 400, "Moderate distance"),
]

for x, y, label in test_points:
    result = check_reachability(L1, L2, x, y)
    status = "REACHABLE" if result['reachable'] else "UNREACHABLE"
    warning = " [NEAR BOUNDARY]" if result['near_boundary'] else ""
    print(f"{label}: ({x}, {y}) -> {status}{warning}")
    print(f"  Distance: {result['distance']:.1f} mm, "
          f"Outer margin: {result['outer_margin_mm']:.1f} mm")
```

## System Application: Welding Seam Following

<InArticleAd />

The weld seam is an arc of radius 150 mm about the point (350, 250) mm, cut into 15 waypoints. For each one the program checks the reach, solves the inverse kinematics by geometry, and warns if the joint angles jump.

All 15 waypoints can be reached. The farthest is 580 mm from the base. The program selects the solution with $\theta_2 > 0$ (elbow-down, the setting passed to it). Along the seam $\theta_1$ rises smoothly from $-15.9°$ to $11.8°$, and $\theta_2$ stays between $68.9°$ and $87.4°$, far from the straight arm.

```python
def welding_seam_path(cx, cy, radius, start_angle, end_angle, n_points=20):
    """Generate waypoints along a circular arc (weld seam).

    Args:
        cx, cy: Center of the arc (mm)
        radius: Arc radius (mm)
        start_angle, end_angle: Arc span (degrees)
        n_points: Number of waypoints

    Returns:
        List of (x, y) waypoints
    """
    angles = np.linspace(np.radians(start_angle),
                         np.radians(end_angle), n_points)
    waypoints = [(cx + radius * np.cos(a),
                  cy + radius * np.sin(a)) for a in angles]
    return waypoints

def plan_weld_path(L1, L2, waypoints, elbow_config="down"):
    """Plan joint trajectories for a weld seam using geometric IK.

    Args:
        L1, L2: Link lengths (mm)
        waypoints: List of (x, y) target positions
        elbow_config: "up" or "down" (preferred elbow configuration)

    Returns:
        List of (theta1, theta2) joint angle pairs
        List of reachability status for each point
    """
    joint_trajectory = []
    status_list = []

    # Index 0 is the solution with theta2 > 0, which is elbow-down for a target to the right.
    sol_idx = 0 if elbow_config == "down" else 1

    for i, (x, y) in enumerate(waypoints):
        reach = check_reachability(L1, L2, x, y)
        status_list.append(reach)

        if not reach['reachable']:
            print(f"  Waypoint {i}: ({x:.1f}, {y:.1f}) UNREACHABLE")
            joint_trajectory.append(None)
            continue

        solutions = inverse_kinematics_2R(L1, L2, x, y)
        if solutions:
            # Select preferred configuration
            idx = min(sol_idx, len(solutions) - 1)
            joint_trajectory.append(solutions[idx])

            # Continuity check: if the chosen solution jumps far from
            # the previous one, the branch just flipped. For real
            # trajectories you would pick the solution that minimizes
            # joint distance from the previous configuration instead.
            if i > 0 and joint_trajectory[i - 1] is not None:
                prev = np.array(joint_trajectory[i - 1])
                curr = np.array(joint_trajectory[i])
                if np.linalg.norm(curr - prev) > np.pi / 2:
                    print(f"  Waypoint {i}: branch switch detected. "
                          f"Continuous paths must not cross between "
                          f"elbow-up and elbow-down.")

            if reach['near_boundary']:
                print(f"  Waypoint {i}: ({x:.1f}, {y:.1f}) "
                      f"near workspace boundary "
                      f"(margin: {reach['outer_margin_mm']:.1f} mm)")
        else:
            joint_trajectory.append(None)

    return joint_trajectory, status_list

# Define the weld seam: arc on a pressure vessel
# Vessel center at (350, 250), radius 150mm, arc from -30 to +60 degrees
L1, L2 = 400, 300
waypoints = welding_seam_path(350, 250, 150, -30, 60, n_points=15)

print("=== Weld Path Planning ===")
print(f"Robot: L1={L1} mm, L2={L2} mm")
print(f"Seam: {len(waypoints)} waypoints\n")

trajectory, statuses = plan_weld_path(L1, L2, waypoints, elbow_config="down")

# Display results
print(f"\n{'Pt':>3}  {'x':>8}  {'y':>8}  {'θ1 (deg)':>10}  {'θ2 (deg)':>10}  {'Status':>12}")
print("-" * 60)
for i, ((x, y), q, s) in enumerate(zip(waypoints, trajectory, statuses)):
    if q is not None:
        t1_d = np.degrees(q[0])
        t2_d = np.degrees(q[1])
        status = "OK" if not s['near_boundary'] else "BOUNDARY"
        print(f"{i:3d}  {x:8.1f}  {y:8.1f}  {t1_d:10.2f}  {t2_d:10.2f}  {status:>12}")
    else:
        print(f"{i:3d}  {x:8.1f}  {y:8.1f}  {'N/A':>10}  {'N/A':>10}  {'UNREACHABLE':>12}")
```

## Design Guidelines

<InArticleAd />

<CardGrid>
  <Card title="Always Verify FK After IK" icon="approve-check">
    Put the joint angles from IK back into FK and check that the end-effector lands on the target.
  </Card>

  <Card title="Choose Elbow Configuration Deliberately" icon="setting">
    For a continuous path (welding, painting, gluing), keep one elbow configuration from start to end. A change in the middle makes the joints jump and can damage the workpiece or the robot.
  </Card>

  <Card title="Avoid Workspace Boundaries" icon="warning">
    Near the outer circle the arm is almost straight, and a small motion of the hand along the arm needs a large change of joint angles. Keep paths 5 to 10% of the reach inside the limits, or move more slowly there.
  </Card>

  <Card title="Use Damped Least-Squares for Numerical IK" icon="approve-check">
    The plain inverse of the Jacobian fails when the arm is straight or folded. Damped least squares adds a small term $\lambda^2 I$ to $J^T J$. Typical values of $\lambda^2$ are $10^{-4}$ to $10^{-2}$.
  </Card>

  <Card title="Initial Guess Strategy" icon="setting">
    Along a path, use the solution of the last waypoint as the first guess for the next one. The solver then needs only a few corrections and stays in the same elbow configuration.
  </Card>

  <Card title="Handle Unreachable Points Gracefully" icon="warning">
    Find the waypoints that cannot be reached before the robot moves. Then move the robot base, split the task into two setups, or use a robot with a longer reach.
  </Card>

  <Card title="Check Joint Limits After IK" icon="warning">
    The geometric IK function knows nothing about joint limits. A target inside the ring can still need a joint angle outside `[theta_min, theta_max]`. Follow every IK call with a limit check:

    ```python
    for (t1, t2) in solutions:
        if (theta1_min <= t1 <= theta1_max
                and theta2_min <= t2 <= theta2_max):
            chosen = (t1, t2)  # use this solution
    ```

    If no solution passes, the real robot cannot reach the target.
  </Card>

  <Card title="Be Consistent About Units" icon="information">
    The programs here use millimeters and radians. Two mistakes are common: degrees given to `np.cos`, and millimeters given to a function that expects meters. Choose one set of units and convert only where the program meets the operator or the hardware.
  </Card>
</CardGrid>

## Summary

<InArticleAd />

- **Forward kinematics** turns joint angles into one end-effector position: add the links, each with the cosine and sine of its direction. For longer arms, a DH table and a product of matrices do the same work.
- **Inverse kinematics** turns a target into joint angles. A target inside the ring has two solutions, elbow-up and elbow-down. A target on the edge has one, and a target outside has none.
- **The geometric method** is exact and fast, but exists only for simple arms.
- **The numerical method** corrects a guess with the Jacobian. It works for any arm and returns one solution.
- **For a path**, test every waypoint for reach and keep one elbow configuration.
